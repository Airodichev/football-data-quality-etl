# Bundesliga 2025/26: ETL и сверка данных

Проект получает матчи Бундеслиги из [OpenLigaDB](https://www.openligadb.de/) и [football-data.org](https://www.football-data.org/), нормализует ответы API и сверяет данные двух источников.

## Обработка

1. `openligadb.py` получает матчи OpenLigaDB, извлекает счёт после 90 минут и выполняет базовые проверки.
2. `football_data.py` получает матчи football-data.org и нормализует счёт, время и статус.
3. `team_matching.py` сопоставляет команды по точному названию, затем применяет два ручных псевдонима (`TSG Hoffenheim`, `FC St. Pauli`). При запуске ETL используются актуальные словари команд из API.
4. `main.py` переводит ID команд OpenLigaDB в ID football-data.org и ищет матч по упорядоченной паре `(home_team_id, away_team_id)` в сезоне 2025/26. Отсутствующие и неоднозначные совпадения учитываются отдельно.
5. Скрипт сохраняет нормализованные матчи и сверку в `football.db` (SQLite) и записывает сводку в `report.txt`.

## Проверки качества

Для каждого источника проверяются повторяющиеся ID и пары команд, обязательные поля, а также целые неотрицательные значения голов. Для завершённого матча счёт обязателен; для будущего матча пустой счёт допустим. Для сопоставленных матчей сравниваются счёт при наличии в обоих источниках, время в UTC и признак завершения. Подсчитываются матчи без соответствия в каждом источнике. Ключи SQLite и обновление существующих строк исключают накопление дублей при повторном запуске.

## Запуск

Требуются Python 3.11+ и зависимости из `requirements.txt`. Файл `.env.example` показывает имя необходимой переменной и может храниться в Git; настоящий `.env` исключён через `.gitignore`. `football_data.py` загружает локальный `.env` через `python-dotenv`, после чего читает `API_football_token` через `os.getenv()`. Токен также можно задать в окружении PowerShell:

```powershell
$env:API_football_token = "ваш_токен"
python main.py
```

## Ограничения

Данные и результаты сверки отражают состояние API на момент запуска. Время OpenLigaDB `matchDateTimeUTC` трактуется как UTC. Счёт сравнивается только при наличии обоих результатов; различие статусов возможно, если источники обновляются не одновременно. Для неоднозначных пар автоматический выбор матча не производится.
